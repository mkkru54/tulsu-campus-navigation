# Навигация по корпусу №9 ТулГУ — векторные планы

HTML/CSS/JavaScript без внешних зависимостей. Этажи 1–7 нарисованы программно: комнаты, стены, дверные проёмы, коридоры, служебные зоны и обозначения лестниц. На сайте нет скриншотов, обрезанных подложек или изображений 2ГИС. Расположение восстановлено вручную по семи скриншотам пользователя от 03.10.2026. Главный корпус «Гл-» исключён.

## Запуск

Нужен Python 3.9 или новее, без установки дополнительных библиотек. Распакуйте архив, перейдите в папку `navigation9` и выполните:

```sh
python3 server.py
```

Откройте http://127.0.0.1:8080. Если порт занят: `python3 server.py --port 8765`, затем http://127.0.0.1:8765. Остановка — Ctrl+C.

Ручная навигация также работает при открытии `index.html` напрямую. Для расписания нужен `server.py`: обычный статический сервер и GitHub Pages не исполняют этот proxy. Для публикации расписания нужен сервер с Python, а фронтенд и `/api/schedule` должны быть доступны с одного адреса.

Введите 113 или 9-113 либо выберите помещение на плане. Ручные поля «Откуда/Куда», лестницы, этажи и масштаб сохранены.

## Расписание

Введите точный номер группы из [публичного расписания ТулГУ](https://tulsu.ru/schedule/). Успешно найденная группа сохраняется в localStorage; кнопка «Забыть группу» удаляет её. Пример `22-13-51` на 07.10.2026 отсутствует в публичном справочнике; реальный запрос `221351` при проверке вернул 344 занятия. Не заменяйте номер группы предположениями.

Показаны текущая и следующая пара **сегодня**, время считается в `Europe/Moscow`, независимо от часового пояса устройства. В перерыв показывается последняя завершённая пара; это предполагаемая начальная точка, которую можно исправить вручную. До первой пары начало выбирается вручную. Следующий учебный день автоматически в маршрут не включается.

Если обе аудитории однозначно распознаны, находятся в корпусе №9 и присутствуют на плане, приложение подставляет их в существующие поля и строит маршрут. Кнопка позволяет построить его повторно. После ручного выбора автоматические обновления не перезаписывают поля; вернуть маршрут по расписанию можно кнопкой. При одновременных занятиях сначала требуется выбрать своё занятие в списке. Подгруппы из источника показаны, если они указаны.

Обрабатываются отсутствие занятий сегодня, окно/перерыв, занятия до начала и после окончания дня, неверная/неизвестная группа, отсутствие опубликованных данных, дата вне опубликованного периода, недоступность источника, неизвестная аудитория и аудитория вне карты. При другой следующей или начальной аудитории внутренний маршрут не строится. Голый номер `714` без корпуса не считается корпусом №9. Суффикс `9-601-2` сохраняется: он не подменяется на `601`.

## Источник и интеграция

Проверено 07.10.2026. [Официальный раздел](https://tulsu.ru/education/timetable) ведёт на `/schedule/`. Его [публичный клиент](https://tulsu.ru/schedule/script.js) использует JSON-запросы:

- `GetDictionaries.php?term=...` — точный номер группы (`SORT=1`).
- `GetDates.php?search_value=...` — период и `SEARCH_FIELD=GROUP_P`.
- `GetSchedule.php?search_field=GROUP_P&search_value=...` — конкретные даты, время, дисциплина, аудитория, преподаватель и подгруппы.

Все адреса находятся под `https://tulsu.ru/schedule/queries/`. Сервер использует эти же запросы, без парсинга HTML и без доступа к личному кабинету. Это интерфейс публичного сайта, а не гарантированно стабильный документированный API: при изменении формата приложение показывает отсутствие данных вместо выдуманных занятий.

У проверенного ответа JSON не было заголовка `Access-Control-Allow-Origin`, поэтому прямой браузерный запрос с другого адреса не подходит. `server.py` отдаёт сайт и `/api/schedule?group=...` с одного адреса; запросы к ТулГУ делает сервер. Адрес источника фиксирован, произвольные URL проксировать нельзя. Есть таймаут 15 секунд на запрос, ограничение размера ответа и кэш успешных ответов 5 минут. Ошибки источника не кэшируются. Сервер слушает только `127.0.0.1`.

Карточки обновляются каждые 30 секунд, данные — каждые 5 минут и при смене московской даты. Данные вставляются как текст. При отказе localStorage расписание продолжает работать без сохранения группы.

## Данные и архитектура

- `data/building.json`: 141 читаемый номер кабинета, служебные точки, геометрия помещений и восстановленный граф. `plans[floor].shapes` содержит прямоугольники с координатами, размерами, типом и подписью; они редактируются независимо. Неизвестные номера перечислены в `pendingRooms` и не выдумываются.
- `data/building.js`: те же данные для запуска через `file://`.
- `plan.js`: рисует SVG-планы из векторных элементов. Коридоры, стены, подписи, ступени лестниц и дверные проёмы создаются программно. Нет элементов SVG image или растровых фонов.
- `app.js`: выбор точек, переключение этажей, масштаб, отображение маршрута и текстовые шаги.
- `routing.js`: независимая Дейкстра, O(V² + E). Двусторонние рёбра с неотрицательными весами; `closed: true` закрывает проход.
- `index.html`, `style.css`: интерфейс.
- `tests/routing.test.cjs`: проверки поиска пути и структуры графа.
- `previews/floor-N.svg`: отдельные векторные планы для просмотра и проверки. Они экспортированы тем же `plan.js`, который использует сайт.

Коридорные узлы отделены от дверей и центров комнат. Маршрут проходит через отдельные точки дверных проёмов; все внутриэтажные отрезки графа горизонтальные или вертикальные. Межэтажные рёбра соединяют лестничные площадки. Актовый зал доступен отдельной точкой на 4 этаже; уровень зала на 3 этаже тоже нанесён. Служебные точки включают гардероб, банкоматы, бюро пропусков, столовую, музей и санузлы.

## Точность

Это ручная векторная реконструкция по [планам 2ГИС](https://2gis.ru/tula?floor=1&m=37.586313%2C54.166954%2F18.94), а не архитектурный обмер. Сохранены взаимное расположение читаемых комнат, западное возвратное крыло, центральное крыло и основные лестничные зоны. Стены выровнены, размеры комнат и проёмы приблизительны. Номера с нечитаемыми подписями не включены в маршруты; подробные границы таких помещений требуют уточнения.

Точное место каждой двери, физическая непрерывность лестниц, доступность проходов и работа лифтов не подтверждены. Межэтажные соединения отмечены `vertical-connection-needs-survey`; двери — `door-needs-survey`. Лестница центрального крыла на 4–5 этажах восстановлена по совпадающим зонам; её соединение также предположительное. Маршруты через лифты не строятся.

Веса — расстояния в координатах плана плюс условный штраф 190 за этаж; это не метры и не минуты. Новый план позволяет точнее привязать маршрут к дверям и коридорам, но сам по себе не подтверждает точность реального маршрута.

## Дополнение

Правьте прямоугольники в `plans[floor].shapes`, координаты узлов `x/y`, поля `rect` и `door` соответствующей комнаты. Узел `door-ID` должен совпадать с её дверью. Рёбра задают фактическую возможность прохода; добавляйте вершины в поворотах, исключайте запертые связи. После обследования исправьте статусы и измерьте расстояния.

Синхронизация данных после изменения JSON:

```sh
python3 -c "import json,pathlib; p=pathlib.Path('data'); d=json.loads((p/'building.json').read_text()); (p/'building.js').write_text('window.BUILDING = '+json.dumps(d,ensure_ascii=False,indent=2)+';\n')"
```

## Проверка

```sh
node --test tests/*.test.cjs
python3 -m unittest discover -s tests -p 'test_*.py'
```

Проверяются исходный граф здания и маршруты, распознавание аудиторий/корпусов, московское время, границы занятий, окно, отсутствие занятий, одновременные пары, другая аудитория, ошибки JSON, неверная группа и недоступные данные. `tests/fixtures/tulsu.json` — небольшой образец реального публичного ответа; обычные тесты не требуют сети.

Необязательная браузерная проверка (Playwright требуется только для теста):

```sh
npm install --no-save playwright
npx playwright install chromium
python3 server.py --port 8765
# В другом терминале:
node tests/browser.cjs
```

Браузерная проверка использует контролируемый ответ расписания и фиксированное время. Сам backend проверяется отдельно тестами и реальным запросом. План корпуса остаётся учебной реконструкцией: наличие маршрута в программе не подтверждает доступность реального прохода.

HTML/CSS и тесты обновлены. Проверено: 11 JavaScript-наборов (включая исходные проверки графа), 6 Python-тестов и браузерный сценарий прошли. Реальный proxy-запрос для группы `221351` вернул 344 занятия. В исходной карте отсутствует `312`; маршрут к ней блокируется до уточнения данных.
