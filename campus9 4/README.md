# Навигация по корпусу №9 ТулГУ

Рабочий статический проект HTML/CSS/JavaScript. На странице доступны планы этажей 1–7, выбор начала и конца по номеру или нажатием на комнату, Дейкстра, маршрут по коридорам, межэтажные переходы, масштаб, текстовые шаги и просмотр графа.

## Запуск

Распакуйте весь архив и откройте `index.html` в современном браузере. Сервер и Интернет не обязательны: планы и данные находятся внутри проекта.

Либо из папки проекта:

```sh
python3 -m http.server 8080 --bind 127.0.0.1
```

Откройте http://127.0.0.1:8080. Остановка: Ctrl+C.

Введите `113` или `9-113`, затем конечную точку и нажмите «Построить маршрут». На плане сначала выберите режим «Откуда»/«Куда», затем нажмите на подписанную комнату. Служебные точки доступны в списке и быстрых кнопках. Маршрут пересчитывается при выборе точки на плане. На узком экране план можно прокручивать горизонтально. «Сброс масштаба» возвращает исходный масштаб.

## Источник и точность

**Условные одинаковые схемы заменены семью планами из предоставленных пользователем скриншотов 2ГИС от 03.10.2026.** Изображения сохранены локально без перерисовки. SVG-маска показывает только корпус №9 и его центральное крыло, исключая главный корпус с подписями «Гл-», улицы, рекламу и интерфейс браузера. Номера комнат и их расположение остаются такими, как на скриншотах.

Источник: [2ГИС, проспект Ленина, 92](https://2gis.ru/tula?floor=1&m=37.586313%2C54.166954%2F18.94). Снимки предоставил пользователь; автоматический доступ к карте позже оказался заблокирован проверкой браузерной политики. Скриншоты — снимок состояния карты, а не гарантия актуальности здания. Использование этих материалов вне учебного прототипа требует проверки условий правообладателя; проект не содержит разрешения на их дальнейшее распространение.

Этаж каждой комнаты определяется по первой цифре номера после `9-` и выбранному уровню справа на скриншоте. Включён **141 читаемый номер**. Комнаты без читаемой подписи остаются видны на плане, но не получают вымышленных номеров и недоступны как точки назначения. Дополнительные номера из [официального перечня кабинетов ТулГУ](https://tulsu.ru/sveden/objects/cabs), чьи места не читаются на снимках, сохранены в `pendingRooms`.

Служебные точки: вход, гардероб, бюро пропусков, банкоматы СберБанка и ВТБ, кофе, буфет, кабинет 007, столовая на 2 этаже, Интернет-институт и помещения 20/22а на 3 этаже, актовый зал и фойе на 4 этаже, музей на 5 этаже. Зал виден также на 3 уровне; для него есть отдельная точка «Актовый зал · уровень 3». Переход между этими уровнями внутри зала не придуман: алгоритм использует лестницы корпуса.

**Ограничения маршрутов:** вершины комнат стоят около центров подписей. Дверные связи с коридором восстановлены приблизительно; точные дверные проёмы не всегда видны. Четыре лестничных узла нанесены около видимых значков. Соединения соседних этажей в одинаковых конструктивных местах предполагаются и требуют проверки на месте. Нет гарантии, что любой проход открыт или что каждая лестница доступна на каждом этаже. Значки лифтов остаются на подложках, но маршруты через лифты пока не строятся. Метры и время не показываются: веса — расстояния в координатах изображения плюс условный штраф 190 за переход между этажами. Это кратчайший путь в восстановленном графе, а не измеренный кратчайший путь в реальном здании.

## Структура

- `index.html`, `style.css`: интерфейс и адаптивная вёрстка.
- `assets/floor-1.png` … `floor-7.png`: неизменённые исходные изображения.
- `data/building.json`: помещения, служебные точки, узлы коридоров, лестницы, рёбра и список уточнений.
- `data/building.js`: те же данные в `window.BUILDING`, для запуска без сервера.
- `routing.js`: независимая Дейкстра для двустороннего графа с неотрицательными весами, O(V² + E). Возвращает `{path, cost}` или `null`. `closed: true` исключает ребро.
- `app.js`: SVG-подложки, маски, интерактивные зоны и линии маршрута; переключение этажей, масштаб, быстрые точки и текстовые шаги.
- `tests/routing.test.cjs`: проверки алгоритма, связности всех узлов и основных служебных точек.

`plans[floor]` задаёт `image`, размер изображения в координатах SVG, `viewBox` и `clipPolygon`. Координаты оцифрованы по показанным превью 1996 × 1248; исходные изображения большей величины SVG масштабирует в эту систему. Никакой общий прямоугольный шаблон комнат поверх изображения не используется.

Узлы имеют `id`, `label`, `floor`, `x`, `y`, `kind`, источник и статус. Четыре лестничных группы: W (запад), C (центральная), D (у восточного коридора), E (восточная). Комнаты присоединены к соседним узлам коридора, а не непосредственно друг к другу. Служебные названия в интерфейсе русские; внутренние ID вроде `hall-4` используются только в данных.

## Что проверить вручную

1. Для каждого кабинета уточнить координаты двери, выход в коридор и актуальный номер. Неподписанные помещения из `pendingRooms` добавить только после подтверждения.
2. Проверить четыре лестничных узла и соединяемые уровни, запертые двери, доступность центрального крыла и входов в зал. Скорректировать либо удалить соответствующие рёбра. Закрытые проходы отмечать `closed: true`.
3. Измерить реальные длины, если нужны расстояния в метрах и время. Проверить работу лифта, прежде чем включать его в граф.
4. Для подробной геометрии коридоров добавить промежуточные вершины поворотов. Исправлять маски в `plans`, если дополните подложки; главный корпус остаётся вне области проекта.
5. После изменения JSON синхронизировать браузерные данные:

```sh
python3 -c "import json,pathlib; p=pathlib.Path('data'); d=json.loads((p/'building.json').read_text()); (p/'building.js').write_text('window.BUILDING = '+json.dumps(d,ensure_ascii=False,indent=2)+';\n')"
```

6. Пройти контрольные маршруты в здании: 113 → 714, 201 → 226в, вход → гардероб, вход → зал на 4 этаже, музей → 601.

## Проверка

```sh
node tests/routing.test.cjs
```

Проверяются обход дорогого ребра, обратное направление, одинаковые точки, неизвестные точки, несвязный граф, закрытые рёбра, неверные веса, уникальность ID, достижимость всех узлов из контрольной точки, наличие семи планов и маршруты к служебным точкам. Эти проверки подтверждают работу алгоритма и целостность данных, но не физическую доступность проходов. Автоматическая браузерная проверка обновлённой версии заблокирована политикой доступа; отрисовку новой версии в живом браузере подтвердить не удалось.
