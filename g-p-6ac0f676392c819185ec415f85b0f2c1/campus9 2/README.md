# Навигация по корпусу №9 ТулГУ

Рабочий учебный прототип на HTML/CSS/JavaScript без зависимостей. Выбор аудитории по номеру или нажатием на схеме, перестановка начала/конца, Дейкстра, маршрут между этажами, переключатель этажей, масштаб и текстовые шаги. Работает без Интернета после скачивания.

## Запуск

Откройте `index.html` двойным нажатием в современном браузере. Данные загружаются обычным скриптом, поэтому сервер не обязателен.

При необходимости локального сервера из папки проекта:

```sh
python3 -m http.server 8080 --bind 127.0.0.1
```

Откройте http://127.0.0.1:8080. Остановка сервера: Ctrl+C.

## Точность и источники (проверено 03.10.2026)

**Геометрия демонстрационная, а не план ТУГИС/2ГИС.** Поиск по названию «ТУГИС» не дал идентифицируемого сервиса с планами корпуса. Проверена карточка 2ГИС здания по адресу проспект Ленина, 92, в том числе действие «Рассмотреть»: поэтажные схемы комнат получить не удалось. Это не доказывает, что их нет в других версиях сервиса. Никаких изображений планов 2ГИС в проекте нет.

- [Страница корпуса №9 ТулГУ](https://tulsu.ru/facilities/academic-building/8): идентификация корпуса и адрес.
- [Официальный перечень учебных кабинетов](https://tulsu.ru/sveden/objects/cabs): существование номеров аудиторий. Это не полный реестр помещений. Из строк корпуса №9 извлечён первый номер аудитории, уникальные номера включены в данные. При дополнении следует проверить строки с несколькими помещениями.
- [Карточка 2ГИС](https://2gis.ru/tula/firm/70000001079767957): адрес и указание «8 этажей».

Существование включённых комнат подтверждается перечнем, но этаж назначен **предположительно по первой цифре номера**. Координаты, порядок комнат, форма коридора, два лестничных узла и их соединения полностью условные. Вход тоже нанесён условно. Аудитория `001` сохранена в `pendingRooms`: этаж не известен, маршрут к ней пока недоступен. На 8 этаже есть только условные коридор и лестницы; комнат из выбранного перечня нет. Номера с суффиксами `а`, `б`, `в` сохранены кириллицей.

Маршрут кратчайший **в демонстрационном графе**, не гарантированно в здании. Веса — условная стоимость, не метры; время пути не вычисляется. Лифты и безбарьерные маршруты не моделируются без подтверждённых данных. Не использовать для реальной навигации до проверки топологии.

## Файлы и архитектура

- `index.html`: форма, этажи, контейнер SVG и источники.
- `style.css`: адаптивный интерфейс, состояния выбора и фокуса.
- `data/building.json`: редактируемая структура здания с происхождением и статусами данных.
- `data/building.js`: те же данные как `window.BUILDING`, для запуска через `file://`.
- `routing.js`: независимая функция `shortestPath(nodes, edges, start, end)`; возвращает `{path, cost}` либо `null`. Граф неориентированный, веса неотрицательные, `closed: true` исключает ребро. Дейкстра с линейным выбором минимума, O(V² + E), подходит для небольшого корпуса.
- `app.js`: обработчики выбора, отрисовка SVG, разделение маршрута по этажам и текстовые шаги. Межэтажный переход показывается лестницей на обоих этажах, а не диагональю на плоскости.
- `tests/routing.test.cjs`: проверки алгоритма и связности всех пар узлов здания.

## Как заменить схему реальными данными

1. Получить поэтажные схемы корпуса и разрешение на их использование; обойти этажи, проверить номера и двери.
2. В `building.json` исправить `floor`, `x`, `y` каждой комнаты. Координаты относятся к системе SVG; `y=250` сейчас задаёт условный коридор. Для новой геометрии исправить фон коридора в `render()` в `app.js` либо добавить подложку плана под рёбрами. Ось y направлена вниз.
3. Расставить вершины в поворотах, развилках, дверях и на лестничных площадках. Не соединять комнату с коридором через стену. Подключить аудиторию `001`, когда станет известен её этаж. Дозаполнить отсутствующие комнаты, включая 8 этаж.
4. Исправить `edges`: `{a, b, weight, kind, status}`. Переходы между этажами соединяют площадки одной реальной лестницы. Удалить неподтверждённые соединения. Закрытые проходы пометить `closed: true`.
5. Внести реальные длины, источники и дату проверки. Заменить `positionStatus: needs-survey`, `floorStatus: inferred-from-number` и `status: needs-survey` только после проверки. Интерфейсные предупреждения обновлять лишь после проверки всего используемого маршрута.
6. Синхронизировать браузерные данные после каждого изменения JSON:

```sh
python3 -c "import json,pathlib; p=pathlib.Path('data'); d=json.loads((p/'building.json').read_text()); (p/'building.js').write_text('window.BUILDING = '+json.dumps(d,ensure_ascii=False,indent=2)+';\n')"
```

7. Проверить маршруты с человеком на месте, включая лестницы, запертые двери и доступность. Для односторонних проходов нужно расширить алгоритм: текущие рёбра двусторонние.

## Проверка

При установленном Node.js:

```sh
node tests/routing.test.cjs
```

Проверяются обход дорогого ребра, обратный маршрут, совпадение начала/конца, отсутствующие точки, несвязный граф, закрытые проходы, неверные веса, уникальность ID и связность всех пар. В браузере: 113 → 714, 202 → 226в, одинаковые точки, неизвестный номер, перестановка точек, выбор комнат мышью/клавиатурой, масштаб и переход по этажам.
